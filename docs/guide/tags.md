# 标签管理

标签是 StarHub 的核心功能，让你可以自由组织 GitHub Stars。

## 理解标签系统

### 什么是标签？

标签是你为仓库添加的分类标识。一个仓库可以有多个标签，一个标签可以关联多个仓库。

### 标签属性

每个标签包含：

| 属性 | 说明 | 示例 |
|------|------|------|
| 名称 | 标签的显示名称 | Web 开发 |
| Emoji | 标签的图标 | 🌐 |
| 颜色 | 标签的背景颜色 | #42b883 |

正式分类注册表还可以包含稳定 ID、中英文名称、别名、中英文说明、示例、排除项、上级分类和侧栏短名称。StarHub 不预装任何用户的个人分类体系，每位用户可以导入自己的注册表。

## 正式分类注册表

主页左上角的 **分类工具** 提供两个入口：

- **导入分类**：粘贴或选择 TXT、CSV、JSON 或 StarHub 备份；
- **管理**：搜索、排序、筛选、编辑、合并和撤销分类迁移。

导入前会显示新增、重命名、合并、元数据更新、不变和冲突数量。存在冲突时不能应用。正式迁移会自动保存当前全部分类和仓库关系，失败时事务回滚，成功后也可在分类管理器中撤销。

::: tip 多用户原则
正式注册表完全由当前用户的数据生成。启用正式注册表后，AI 只能选择其中的分类；没有进入注册表的普通分类仍会保留，但不会作为 AI 分类选项。
:::

### 通用 JSON 示例

```json
{
  "version": "team-taxonomy-2026.1",
  "tags": [
    {
      "categoryId": "web.frontend",
      "nameZh": "前端开发",
      "nameEn": "Frontend Development",
      "aliases": ["Web UI"],
      "descriptionZh": "浏览器端界面和交互开发。",
      "descriptionEn": "Browser interface and interaction development.",
      "examples": ["Vue", "React"],
      "exclusions": ["后端 API"],
      "level1": "软件开发",
      "level2": "前端"
    }
  ]
}
```

`categoryId`/`registryKey` 应在同一分类体系中长期稳定。修改显示名称时不要更换 ID。

## 创建标签

<p align="center">
  <img src="../public/screenshot-create-tag.png" alt="创建标签" style="max-width: 400px; width: 100%;" />
</p>

1. 点击左侧标签区域的 **+** 按钮
2. 输入标签名称
3. 选择 Emoji 和颜色
4. 点击 **创建**


## 删除标签

1. 在左侧标签列表中，悬停在标签上
2. 点击 **删除** 图标 (🗑️)
3. 确认删除

:::warning
删除标签后，所有仓库与该标签的关联都会被移除。此操作不可恢复！
:::

## 为仓库添加标签

### 单个仓库

<p align="center">
  <img src="../public/screenshot-add-tag.png" alt="批量添加标签" style="max-width: 400px; width: 100%;" />
</p>

1. 点击仓库，打开详情面板
2. 在标签区域点击 **+**
3. 选择已有标签或创建新标签

### 批量添加

<p align="center">
  <img src="../public/screenshot-batch-add-tag.png" alt="批量添加标签" style="max-width: 400px; width: 100%;" />
</p>

1. 点击仓库列表顶部的 **选择** 按钮
2. 勾选要操作的仓库
3. 点击 **批量设置分类**
4. 选择要添加的标签
5. 点击 **确定**

## 移除标签

### 从单个仓库移除

1. 点击仓库，打开详情面板
2. 点击标签上的 **×** 按钮

### 批量移除

1. 进入选择模式
2. 选中仓库
3. 点击 **批量设置分类**
4. 取消勾选要移除的标签

## 使用标签筛选

点击左侧的任意标签，仓库列表只显示包含该标签的仓库。

### 组合筛选

1. 点击一个标签进行筛选
2. 同时使用搜索框缩小范围

## 标签最佳实践

### 1. 保持简洁

- 避免创建过多标签
- 使用通用的分类名称
- 定期清理不用的标签

### 2. 使用层级

普通分类可以继续使用命名约定：

```
前端 / React
前端 / Vue
后端 / Node
后端 / Go
```

正式注册表可以使用 `level1` 和 `level2`。当前侧栏按层级排序并显示较短的 `level2`，数据关系仍由稳定分类 ID 管理。

### 3. 结合 AI 分类

1. 先导入并确认适合自己的正式注册表
2. 先用小样本评估 AI，再扩大任务
3. 审核低置信度项目，必要时使用 README 增强
4. 为特殊项目保留普通自定义分类
