# AI 智能分类

StarHub 支持使用 AI 为 GitHub Stars 生成分类草稿。该功能仍是实验性功能：模型结果必须经过人工审核，确认前不会写入正式分类。

## 功能概述


AI 智能分类会分析每个仓库的：

- 仓库名称
- 仓库描述
- 编程语言
- Topics 标签
- 仅对疑难项按需读取的 README 摘要

然后自动将仓库归类到合适的标签中。

| 服务商 | 默认模型 | 优势 | 价格 |
|--------|----------|------|------|
| OpenAI | gpt-4o-mini | 严格 JSON Schema | 以平台当前价格为准 |
| Claude | claude-sonnet-4-6 | 原生 JSON Schema | 以平台当前价格为准 |
| DeepSeek | deepseek-chat | 原生 JSON 模式 | 以平台当前价格为准 |
| 通义千问 | qwen-plus | 原生 JSON 模式 | 以平台当前价格为准 |

### 步骤 1：获取 API Key

选择一个 AI 服务，获取 API Key：

- **OpenAI**: https://platform.openai.com/api-keys
- **Claude**: https://console.anthropic.com/settings/keys
- **DeepSeek**: https://platform.deepseek.com/api_keys
- **通义千问**: https://dashscope.aliyun.com/
- **智谱 AI**: https://open.bigmodel.cn/

### 步骤 2：配置 StarHub

1. 点击右上角用户头像 → **设置**
2. 在 **AI 分类设置** 区域：
   - 选择 AI 服务商
   - 输入 API Key
   - （可选）自定义 API 地址和模型
3. 点击 **保存**

## 使用 AI 分类

<p align="center">
  <img src="../public/screenshot-ai-classification-mode.png" alt="AI 分类模式" style="max-width: 400px; width: 100%;" />
</p>

### 触发分类

1. 返回主页
2. 在左侧标签区域，点击 **AI 分类** 按钮（✨）
3. 选择 100、200、500 个仓库的试验样本，或明确选择全部
4. 等待元数据初筛完成
5. 在审核窗口中标记分类正确或错误，查看真实准确率
6. 对人工判错或置信度低于 65% 的疑难项启动 README 增强
7. 对比增强前后结果；只有点击“采用并标记正确”才会修改当前草稿
8. 调整分类或取消不确定项目后，点击确认写入

### 分类模式

当前安全模式只处理没有任何分类的仓库。AI 不会清空、覆盖已有分类，也不会自行创建新分类。

模型只能返回实际分类的稳定 `category_id`。如果还没有实际分类，请先创建分类，或者在设置中将预设同步到实际分类。

### 分类过程

1. StarHub 默认建议随机抽样 200 个仓库，并保存抽样种子
2. 元数据初筛按批次处理仓库（默认 50 个/批），不会读取 README
3. 每一批结果都会校验仓库 ID、分类 ID、置信度和理由
4. 成功结果进入审核队列，此时正式分类尚未改变
5. README 增强每批最多处理 5 个疑难项，可暂停、恢复和重试
6. 用户确认后，选中的结果通过单次 IndexedDB 事务写入
7. 左侧分类栏可撤销最近一次 AI 分类写入

:::warning
置信度低于 65% 的项目默认不选中，必须人工确认。置信度只是模型自评，不等于真实准确率。
:::

## 高级配置

### 批次大小

控制每次 AI 请求处理的仓库数量：

| 设置 | 说明 |
|------|------|
| 10 | 小批量，适合测试 |
| 30 | 中等批量 |
| 50 | **默认**，平衡效率和准确性 |
| 100 | 大批量，速度快但可能影响准确性 |

:::tip
如果分类不准确，尝试减小批次大小。
:::

### 读取 README

<p align="center">
  <img src="../public/screenshot-ai-classification-readme.png" alt="AI 分类 README" style="max-width: 400px; width: 100%;" />
</p>

README 不再作为全量分类开关。系统只会选择以下疑难项：

- 人工标记为错误的结果，包括高置信度错误；
- 置信度低于 65% 的结果。

启动前会明确显示疑难项数量。每个 README 最多提取 12,000 个字符，移除代码块、图片、HTML 和徽章后缓存在本机 IndexedDB；仓库有新推送时缓存自动失效。README 和仓库元数据按不可信内容处理，模型必须忽略其中的指令或提示注入。

增强结果与原结果并排显示，包含分类变化、置信度和证据理由。增强生成本身不会覆盖草稿，也不会写入正式分类。

## 分类效果优化

### 提高准确率

1. **先完成 200 个随机样本评测**：查看真实准确率和主要错误分布
2. **标记高置信度错误**：README 增强不仅依赖低置信度阈值
3. **只增强疑难项**：利用更多证据，同时控制请求和 Token 成本
4. **逐项比较增强结果**：统计修正数与增强退化数

### 降低成本

1. **使用元数据初筛**：绝大多数仓库不发送 README
2. **使用经济模型**：gpt-4o-mini 或 deepseek-chat
3. **只分类未分类仓库**：避免重复分类

## 手动调整

AI 分类不可能 100% 准确，建议：

1. 先使用 200 个随机样本验证分类表和真实准确率
2. 在审核窗口中检查低置信度结果，也抽查高置信度结果
3. 修改错误分类，或取消勾选后再提交
4. 写入后发现系统性问题时，立即使用撤销按钮

### 移动仓库到其他分类

1. 点击仓库查看详情
2. 移除当前标签
3. 添加正确的标签

## 常见问题

### 分类失败？

1. 检查 API Key 是否正确
2. 确认账户余额充足
3. 检查网络连接
4. 尝试减小批次大小

### 分类不准确？

1. 将错误结果标记为“错误”
2. 对疑难项运行 README 增强并比较前后结果
3. 如果错误集中在类别边界，先完善分类描述、示例和排除项，再创建新任务

### 速度太慢？

1. 先运行 100–200 个仓库的试验任务
2. 不要对全部仓库抓取 README；只增强疑难项
3. 暂停任务后可写入当前已审核结果，其余仓库以后创建新任务继续
