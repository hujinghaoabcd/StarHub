# 取消 Star 按钮同步状态热修

## 问题

项目详情中的“取消 Star”按钮原先使用：

```text
repo.private || repoStore.isSyncing
```

作为禁用条件。StarHub 每次进入首页都会在后台同步全部 Stars；当仓库较多或网络较慢时，按钮会长时间保持不可点击，看起来像功能完全失效。

## 修复

- 按钮只在仓库为私有仓库时禁用；
- 用户确认取消 Star 后，若后台同步仍在运行，则主动将该同步标记为取消；
- 状态层执行取消 Star 时再次防御性取消同步；
- 已经进入 IndexedDB 写队列的同步事务仍按队列顺序完成，随后取消 Star 的本地删除事务会最终移除仓库和标签关系；
- 取消中的旧同步不会再把远端旧快照更新回内存列表。

## 回归测试

`tests/unstar-sync-hotfix.test.mjs` 检查：

1. 按钮不再因为 `repoStore.isSyncing` 被禁用；
2. 状态层包含受控的 `cancelRepositorySync`；
3. 取消 Star 不再抛出“同步正在进行”的拒绝错误。

## 人工验收

1. 打开 StarHub 后立即进入任意公开仓库详情；
2. 在后台同步尚未结束时确认“取消 Star”按钮可点击；
3. 点击并确认操作；
4. 确认出现“已暂停后台同步”提示；
5. 完成授权后确认 GitHub Star、本地仓库和标签关系均被移除。
