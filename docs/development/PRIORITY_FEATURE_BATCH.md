# 优先功能批次：项目链接、取消 Star、全局排序与大分页（历史归档）

:::warning 历史文档

## 目标

本批优先完成四项用户功能：

1. 在项目详情区显示 GitHub 仓库、About 网站和实际 GitHub Pages 地址；
2. 支持在 StarHub 内取消公开仓库的 Star；
3. 排序作用于全部筛选结果，而不是只排序当前页；
4. 分页大小上限增加到 1000。

## 排序与分页

支持更新时间、Star 数、创建时间和项目名称，每个字段均可升序或降序。固定处理顺序为：

```text
筛选 → 全量排序 → 分页
```

可选分页大小：`50 / 100 / 200 / 500 / 1000`。即使结果只有一页，分页大小控件仍保持可用。

## 项目链接

详情区按需读取：

- 仓库 `html_url`；
- GitHub About 的 `homepage`；
- GitHub Pages API 返回的实际 `html_url`。

未配置 About 或未启用 Pages 时明确显示未配置状态，不根据仓库名称猜测网址。Pages 元数据优先使用当前登录会话请求；权限不足时，公开仓库再回退到匿名读取。

## 取消 Star

取消 Star 使用 GitHub 官方 REST API。只有远端请求成功后，才在共享本地数据写队列中删除：

- IndexedDB 中的仓库；
- 该仓库对应的 `repoTags` 关系；
- 当前内存列表和详情选择状态。

操作必须二次确认；仓库同步期间禁止执行，避免旧同步快照把刚取消的仓库重新写回。

## OAuth 权限边界

日常登录仍只申请 `read:user`。首次执行取消 Star 时才按需请求 `public_repo`：

- GitHub OAuth App 没有仅用于修改 Star 的独立作用域；
- 授权前明确说明 `public_repo` 还包含更广泛的公开仓库写能力；
- 不申请私有仓库 `repo` 权限；
- 授权成功后替换当前 12 小时浏览器会话中的 token，并自动重试取消 Star；
- 已有 `repo` 权限的会话自动视为满足 `public_repo`，不会重复请求。

## 自动验证

- 全量排序：升序、降序、名称、日期和 Star 数；
- 分页大小：允许 1000，拒绝未支持值；
- OAuth scope：空值、分隔符、精确权限和上位权限包含关系；
- Lint、TypeScript、单元测试、CSP、OAuth 文档、生产依赖审计、GitHub Pages 与 Cloudflare 构建。
