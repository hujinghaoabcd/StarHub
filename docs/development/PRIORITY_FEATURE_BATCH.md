# 优先功能批次：项目链接、取消 Star、全局排序与大分页

## 目标

本批优先完成用户直接提出的四项功能：

1. 在项目详情区显示 GitHub 仓库、About 网站和实际 GitHub Pages 地址；
2. 支持在 StarHub 内取消公开仓库的 Star；
3. 排序作用于全部筛选结果，而不是只排序当前页；
4. 分页大小上限增加到 1000。

## 排序规则

支持以下字段：

- 更新时间；
- Star 数；
- 创建时间；
- 项目名称。

每个字段均支持升序和降序。处理顺序固定为：

```text
筛选 → 全量排序 → 分页
```

因此翻页后仍保持同一套全局顺序。

## 项目链接

详情区按需读取：

- 仓库 `html_url`；
- GitHub About 的 `homepage`；
- GitHub Pages API 返回的实际 `html_url`。

未配置 About 或未启用 Pages 时明确显示未配置状态，不猜测网址。

## 取消 Star

取消 Star 使用 GitHub 官方 REST API。远端成功后，在同一受控本地数据写队列中删除：

- IndexedDB 中的仓库；
- 该仓库对应的 `repoTags` 关系；
- 当前内存列表和详情选择状态。

操作必须二次确认；仓库同步期间禁止执行，避免旧同步快照把刚取消的仓库重新写回。

## OAuth 权限边界

GitHub OAuth App 对公开仓库 Star 写操作要求 `public_repo`。该作用域比单独的 Star 操作更宽，因此：

- 只申请公开仓库权限；
- 不申请私有仓库 `repo` 权限；
- 界面明确说明权限用途；
- 已登录的旧会话需要退出后重新授权才可使用取消 Star。

## 验收

- 全量排序测试覆盖升序、降序、名称、日期和 Star 数；
- 分页大小允许 1000，拒绝未支持值；
- 生产构建、CSP 校验、OAuth 文档校验和生产依赖审计全部通过；
- 真实账户人工验证 About、Pages、取消 Star 和本地关系清理。
