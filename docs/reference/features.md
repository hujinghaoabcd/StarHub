# 功能清单与成熟度

本页用于区分已经上线的功能、实验能力和计划，避免 README、界面与交接文档相互矛盾。

## 已上线

| 领域 | 当前能力 |
|---|---|
| 认证 | GitHub OAuth、state、PKCE、Cloudflare code 交换、12 小时会话 |
| 同步 | 分页同步 Stars、进度、限流处理、本地关系保留、取消 Star |
| 浏览 | 搜索、语言/分类/重点筛选、多种排序、50–1000 分页 |
| 详情 | 仓库摘要、About、Pages、README、GitHub、取消 Star、分类编辑 |
| 分类 | 创建、编辑、名称导入、批量关联、删除 |
| 分类治理 | 稳定 ID、双语元数据、别名、预览、重命名、合并、冲突、快照撤销 |
| 重点标记 | 独立标记、筛选与优先排序，不污染分类 |
| AI 第一轮 | 五类供应商配置、正式注册表约束、持久任务、Schema 和 ID 校验 |
| AI 审核 | 置信度、理由、人工选择、质量评价、分页、确认写入与撤销 |
| README 第二轮 | 低置信度/人工标错候选、缓存、截取、批量增强 |
| 数据 | IndexedDB v8、StarHub v4 备份、正式注册表导入 |
| 体验 | 中英文、明暗主题、长列表优化、详情渲染隔离 |

## 实验性或需要继续验证

- AI 分类准确度取决于用户注册表、供应商和仓库信息，不承诺固定百分比；
- 大规模“全部未分类”任务已有分段和恢复能力，但仍需更多真实 10k–20k 数据压力测试；
- README 二阶段已具备链路，候选策略、成本统计和跨会话体验仍可优化；
- 国际化主流程已覆盖，但仓库内容、AI 原始理由和少量错误兜底可能仍为源语言；
- 分类注册表是通用框架，不提供适合所有人的内置固定分类清单。

## 尚未实现

- StarHub 账号、服务端数据库、跨设备实时同步与团队协作；
- 正式启用的 PWA 和完整离线模式；
- 自动抓取全部 README 后全量分类；
- 云端托管或代管用户 AI Key；
- 自动决定用户应使用哪套分类体系；
- AI 任务、README 缓存和迁移快照的完整备份；
- 完整 AI 历史数据清理入口。

## 产品原则

1. 通用工具优先，不把维护者个人分类作为所有用户默认标准；
2. 用户本地数据优先，不为便利扩大服务端数据收集；
3. AI 只能建议，正式注册表和最终写入由用户控制；
4. 高风险迁移必须可预览、原子执行并可撤销；
5. 大规模功能必须可暂停、恢复、重试和统计成本；
6. 文档中“计划”不得描述成“已上线”。
