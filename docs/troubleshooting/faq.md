# 常见问题

## 同步与仓库数量

### 首次同步为什么很久？

首次登录需要分页读取全部 Stars。数千至数万个仓库需要更多 GitHub API 请求和 IndexedDB 写入，顶部会显示同步进度。不要在同步期间反复刷新或同时打开多个 StarHub 标签页。

### 页面数量与 GitHub 不一致？

先等待同步结束，再检查搜索词、分类、语言、重点标记和排序筛选。StarHub 的“未分类”指当前没有任何 `repoTags` 关系的仓库，不等同于 AI 尚未审核。

### 取消 Star 后为什么又出现？

确认 GitHub 请求成功并完成下一次同步。若 GitHub 权限、网络或限流导致取消失败，StarHub 不应只删除本地记录。保留错误信息并重试，不要手工删除 IndexedDB 仓库。

## 详情与 README 卡顿

当前详情面板会请求并渲染 README。项目 README 极大、包含复杂 HTML/代码块，或在短时间快速切换许多项目时，浏览器可能出现明显负载。项目已加入请求取消、渲染 worker 和缓存隔离，但仍建议：

1. 等当前详情完成或关闭后再打开下一个；
2. 更新到最新浏览器并刷新生产页面；
3. 在无痕窗口判断是否为旧缓存或扩展影响；
4. 记录具体仓库 URL，以便复现异常 Markdown；
5. 若整个页面无响应，选择浏览器“等待”，不要立即清空站点数据。

详情卡顶部按钮使用独立操作区，不应覆盖描述文字；若仍覆盖，请提供窗口宽度、缩放比例和截图。

## AI 分类

### “JSON 格式错误，已拒绝自动修补”是什么意思？

供应商返回了截断或无效 JSON。StarHub 故意不再用正则补全后写库，因为“可解析”不代表结果完整。任务会记录失败项，可以降低批次、换支持 JSON 输出的模型或重试失败项。

### “未知分类 ID”是什么意思？

AI 返回的 ID 不属于该任务锁定的正式注册表版本。可能是模型凭空创造 ID，也可能是任务运行期间分类被合并或注册表发生变化。StarHub 会拒绝该批，防止写入不存在的分类。暂停任务，检查注册表版本，然后创建新任务或重试失败项。

### 为什么暂停时不能点击确认写入？

只有存在通过 Schema、批次 ID 白名单和注册表验证的草稿时才能写入。当前版本允许在暂停状态写入已选有效草稿；提交后会结束本次任务，未处理仓库以后通过新任务继续。失败项或无效输出本身不能被确认写入。

### 为什么低于 65% 的项目没有默认选中？

这是人工审核保护。低置信度结果可修改分类、标记评价，或进入 README 增强；不能用“全选”替代审查。

### 为什么 README 增强只处理少量项目？

第二阶段只针对低置信度或人工标错的候选，并限制每批数量与截取长度，以控制 GitHub API、token、费用和浏览器内存。高置信度元数据结果不应无条件重新读取全部 README。

### AI Key 保存在什么地方？

Key 存在 `sessionStorage`；连接偏好可存于 `localStorage`，但不包含 Key。关闭对应标签页/浏览会话或点击清除可移除 Key。当前 Key 没有独立的 12 小时计时 TTL。

## 分类与重点标记

### 普通分类和正式注册表有什么区别？

普通分类可快速创建和导入名称；正式注册表额外包含稳定 ID、中英文名称、别名、说明、示例、排除项和版本，AI 只能从当前确认的正式注册表选择。

### 重命名会丢项目吗？

安全重命名只改显示元数据，不改变分类稳定 ID。合并会在事务内把源关系迁移到目标并去重，操作前创建快照。如预览存在冲突，应用按钮应保持禁用。

### 重点标记是分类吗？

不是。重点标记保存在独立表中，可用于排序和过滤，不创建分类，也不改变 AI 注册表。

## 离线、PWA 与多设备

StarHub 当前不是已启用的 PWA，也没有云端数据同步。静态资源可能被浏览器缓存，但不能承诺完整离线使用。每个浏览器 Origin 有独立 IndexedDB；换设备、浏览器或部署域名时需要手工导出和导入备份。

## 数据会上传到 StarHub 服务器吗？

StarHub 没有用户数据后端。OAuth API 只交换授权 code。GitHub 数据由浏览器直接请求 GitHub；AI 分类所需的仓库元数据和可选 README 摘要会在用户启动任务后发送到所选 AI 供应商。
